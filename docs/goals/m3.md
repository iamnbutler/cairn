# Goal: M3, Pairs: images, JSON and a package-built app

Cairn is research into building user interfaces where every thing a person can do is a
**claim** with a durable id, and every claim carries machine-checked evidence. M1 proved the loop
on TodoMVC and M2 on Yap. M4 to M7 build a Bluesky client ([roadmap](../roadmap.md)), which needs
images, JSON and many requests in flight at once. M3 puts those in place on an app small enough
to finish: a memory game.

Pairs deals a grid of face-down cards. Flip two; if they match they stay up, if not they flip
back after a second. Decks are theme packs: a JSON manifest and a set of images, from disk or
from a URL. Best scores are saved per pack.

## The demo

Pairs lives in its own repository, `iamnbutler/pairs`, and is the first app built only
through the package path: `cairn new pairs --bin`, `cairn add cairn`, `cairn add cairn_json`,
`cairn build`. Nothing in it reaches into the cairn repository. `make pairs` builds and installs a
signed `Pairs.app`; it opens with a bundled pack and can open a pack from a folder or a URL.

## Done means

1. **The app.** New game, flip, match, mismatch flipping back after 1 s, a move and time counter,
   a win screen, best moves and time per pack saved, the bundled pack, opening a pack from a folder
   or an `https` URL, and switching packs mid-game. A pack that fails to parse or whose images
   fail shows what went wrong and leaves the current game alone.
2. **Images in Cairn.** The framework, not the app, gains:
   - an image node in `UI.Node` with an integer size, known to Lean before the pixels are;
   - an effect that loads an image (file or URL) and answers its size or a failure. The host
     decodes, caches and paints with Metal; Lean never holds pixels;
   - placeholder and failed states, so layout doesn't jump when an image arrives;
   - each piece an `assume` claim with a trusted-base fuzz check, as M1's codecs.
3. **JSON as a package.** `cairn_json`, its own repository and registry package, starting
   from Yap's total JSON parser and encoder, with proofs that `decode (encode v) = v` and that
   `decode` is total, and a trusted-fuzz comparison against Foundation's `JSONSerialization`. Yap
   moves to it.
4. **Requests in flight.** Loading a pack issues one request per image with at most 6 in flight;
   switching packs cancels the rest. This is the first slice of the async work M4 needs:
   - a late reply for a cancelled or old pack never changes the board;
   - every issued request is answered, cancelled or still counted as live; none is lost.
5. **A grid that follows the window.** Columns come from the window's width; resizing reflows
   the cards. Proved for every width: no two cards overlap, every card is inside the window, and
   the order is reading order.
6. **Claims and proofs** with M1's rules (no `sorry`, standard axioms only):
   - the deal, from a host-supplied seed, is a permutation with every face exactly twice;
   - at most two unmatched cards face up; a matched card stays matched;
   - the game is won exactly when every card is matched, and it always can be;
   - moves count pairs flipped; a best score only improves;
   - menu presence and enablement, as before.
7. **The package path works end to end.** `cairn-link` links each dependency's `libs` (step 3 of
   [packages-and-std](../packages-and-std.md)); CI in pairs builds it against the
   registry (#86); `cairn_json` and a new `cairn` release are published.
8. **Fuzzed, measured, written down.** Random clicks, resizes, image replies (slow, failed, out
   of order, duplicated) and pack switches, checking the invariants every step. Pack load time and
   memory with 100 images, in `bench/`. Every new assumption in `docs/trusted.md`.

## Not in M3

Scrolling (the grid always fits), text input, authentication, image formats beyond what the host
decodes natively, animation beyond the flip-back timer, other platforms.

## Order of work

1. **In parallel:** the image node and load effect, on a small example in this repository;
   `cairn_json` with its proofs; `cairn-link` linking dependencies' `libs`.
2. **Pairs as a headless model:** deck, deal, rules and the request bookkeeping, with claims,
   proofs and fuzz, before any UI.
3. **Pairs on Cairn** in pairs: grid, images, packs, scores.
4. **Ship:** release cairn and cairn_json, sign and install, benchmarks, docs.

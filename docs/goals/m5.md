# Goal: M5, Sky: acting on Bluesky

Cairn is research into building user interfaces where every thing a person can do is a
**claim** with a durable id, and every claim carries machine-checked evidence. M4 built the
reading half of a Bluesky client, [Sky](m4.md): sign in, keep the session, read the home feed
however long it gets. M5 is the acting half ([roadmap](../roadmap.md)).

Sky gains like, repost, follow and mute, and notifications. Every act shows in the frame after
the press, before the server has answered, and is rolled back in words if the server refuses it.
The claim this milestone exists for: **once every reply is in, whatever order the replies came in,
each post shows what the server holds, and its count is the server's.** Posting, replies and
quotes are M6.

## The demo

Sky 0.4.0, from the registry like M4's (`cairn add cairn`, `cairn add cairn_json`,
`cairn add cairn_atproto`, `cairn bundle --sign`). Nate likes, reposts, follows and mutes from
their own timeline and reads their notifications with it. Every path also runs against the fake
PDS on `127.0.0.1`, which now keeps the tester's likes, reposts, follows and mutes, has other
accounts acting, lags as the real AppView does, and loses replies after acting on them.

## How an act works

Each kind of act is a `Cairn.Optimistic` table in Sky: likes and reposts keyed by post URI,
follows and mutes by DID. Every place a post or an account appears reads the same table, so a
post liked in Notifications shows liked on Home.

- **Pressing** mints a record key (a TID, from the clock, strictly increasing in a session) and
  sets the table. The table's `want` is what's shown, at once. If no write is in flight for that
  key, it sends one: `putRecord` with the key it chose, or `deleteRecord` (mutes are
  `muteActor` / `unmuteActor`). Presses while one is in flight only change `want`; when the
  write is answered, one more is sent if `want` and the server's value still differ. Rapid
  presses never stack writes.
- **Acknowledged** (2xx): the server's value is the written one.
- **Refused** (4xx, including a rate limit): the key goes back to the server's value in that
  step, and the app says so ("Couldn't like @alice's post: rate limited, try again in 40 s"),
  in a line and to VoiceOver.
- **Lost** (a timeout, a network failure, a 5xx): the write may or may not have happened. The
  key stays as shown, in doubt, and the table reads the record back with `getRecord` from the
  account's own PDS, which reflects every write it acknowledged. The read settles it as
  acknowledged or refused. A failed read is retried on a backoff. The write is never sent blind
  a second time, though doing so would be harmless: a `putRecord` with a key already written,
  and a `deleteRecord` of a missing record, change nothing.
- **Views** (timeline pages, `getPosts`, notifications' subjects) are taken for a key only if it
  hasn't been written this session. The AppView indexes writes late, so a page fetched after a
  like can still say "not liked"; such a view never undoes a confirmed act. A written key that a
  view disagrees with, with nothing in flight, is read back (someone liked it from the web).
- **Counts.** A view's count includes the person's own like exactly when its `viewer.like` is
  set, so Sky shows `count − [viewer.like] + [shown liked]`. With nothing in flight that is the
  server's count, unless other accounts liked or unliked it since the view, which no client can
  know until it looks again.

The proof is in two parts. `Cairn.Optimistic` proves convergence against an abstract server (a
register per key, idempotent writes, any interleaving and loss of replies); Sky instantiates it
for its tables. The fuzzer then checks the same statement end to end against the fake PDS's
world, which is the concrete server, with its lag, other accounts and faults.

## Mute

Muting shows at once, like any act, from `want`: the posts and reposts of a muted account leave
the feed and notifications in the step of the press, and come back on unmute. Nothing is dropped
from the feed itself; only what's shown is filtered, so a page fetched before the mute (which
the server hadn't filtered) is filtered too. A hidden row keeps its key and lays at zero height,
so the virtual list's anchor holds and the reader doesn't move. A quote or reply parent by a
muted account reads "Post from an account you muted".

## Notifications

The list is a `Paged` list like the feed, so load more, refresh and their race are the proofs
already made, moved into `cairn_atproto` (#250). Likes of the same post that are next to each
other become one row, as do reposts and follows; mentions, replies and quotes are rows of their
own, with the post's actions. Unread is polled every 60 s while signed in. When the list is on
screen, its newest notification that has appeared is marked seen (`updateSeen`), through a
one-key optimistic table, so the count drops to zero at once and comes back if the call is
refused. Live updates over a websocket are M7.

## What the client assumes about the server

These are `cairn_atproto` `assume` claims (#249), not Cairn's trusted base: each is checked
against the fake PDS, whose Lean model proves it of itself (#251), and once against the real
network with the installed app (#258).

- A `putRecord` with a given key, and a `deleteRecord`, are idempotent.
- `getRecord` on the account's own PDS reflects every write it acknowledged.
- A post view's count and its `viewer` state are from the same moment.
- A write refused with `ExpiredToken` was not applied, so the session machine's one retry after
  a refresh is safe.

## Not in M5

Posting, replies, quotes and rich text (M6); columns, several windows, live updates (M7);
blocking, lists and moderation labels; threads, profiles, custom feeds and search; several
accounts; OAuth; system notifications (banners); video and GIF playback. Open performance
issues from M4, image memory ([#240](https://github.com/iamnbutler/cairn/issues/240)) and the
first frame of a fling ([#241](https://github.com/iamnbutler/cairn/issues/241)), stay where they
are; #256 checks M5 doesn't make them worse.

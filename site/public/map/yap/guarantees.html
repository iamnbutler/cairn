^311

A shortcut never sends

invariantproved
Does

While the dictation key is held and another key has gone down with it (a shortcut such as the key plus C), nothing the host reports leads to a clip's upload for transcription: not the key's release, not a new key in config.json, not a reply, and never the menu. Only the clock (or a timer) can, for a hands-free recording that hits its ten-minute limit (app_shortcut_never_sends, shortcut_never_sends).

^347

A mark waits for the appends

invariantproved
Does

Yap marks a typed transcript's line in its day file ("typed":true) by rewriting the file, and the host runs requests concurrently, so a line is only known to be there once its append is answered. The app keeps the day-file appends it has sent and not heard back from (Io.appends): every append it sends is kept, with its line, and one leaves only when a reply with its id arrives; a line is saved for marking only when the reply to its append says it worked; and a mark's read goes out only for a saved line, when no append is in flight after the message, so never before its own append is answered nor in the same frame as another. The menu starts no mark and drops no append (receive_tracks, receive_answers, receive_saves, receive_marks, menuStep_marks).

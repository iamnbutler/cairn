Third milestone: Pairsnext

2026-10-24

Can an app be built from packages alone, with images and requests it doesn't control? Pairs is a memory game: a grid of face-down cards, flip two, keep them if they match. Decks are theme packs, a JSON manifest and a set of images, from a folder or a URL. It is small enough to finish, and it needs what the Bluesky client after it will: images, JSON and many requests in flight at once.

  1. Images in Cairn: an image node whose size Lean knows before the pixels arrive, and an effect that loads one. The host decodes and paints; Lean never holds pixels.
  2. JSON as its own package, cairn_json, with a proof that decoding what was encoded gives it back.
  3. Requests in flight: at most 6 at once, and switching packs cancels the rest. A late reply for an old pack never changes the board.
  4. A grid that follows the window, proved for every width: no two cards overlap and every card is inside it.
  5. Proofs about the game: the deal has every face exactly twice, at most two unmatched cards are face up, and every game can be won.

Pairs lives in its own repository and is built only through the package path: cairn new pairs --bin, cairn add and cairn build.

Second milestone: Yap on Cairnnow

2026-10-23

Can claims hold up on real software someone uses every day? Yap is a small dictation app for the Mac: hold a key, talk, and the transcript is typed into the app in front. Almost all of it lives outside its window, so Cairn has to learn the outside world first.

  1. Effects: the clock and timers, requests the host performs and answers, and outside inputs like a global key and the microphone. Each one is a recorded assumption, fuzzed.
  2. New surfaces: a native menu bar menu built from Lean, and an overlay that never takes focus.
  3. Proofs about dictation: a shortcut never sends, a transcript is saved before it is typed, a late reply never types, every recording ends.
  4. Yap rebuilt on Cairn, signed and installed, and used for a real day of work.

Yap lives in its own repository now, yap-cairn, and depends on a tagged release of Cairn the way any app would. Getting it there made Cairn a package, with a cairn command and claim ids scoped by package: Yap's are yap^N.

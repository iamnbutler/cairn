Cairn.Claims.Move

lean/Cairn/Claims/Move.lean

Moves and the update they induce.

A move is one thing a person can do. It owns a claim id and answers the actions that name a control of that claim (^5, or ^5#12 for the control with key 12). For each kind of action it answers (press, edit, …) it has a handler: what happens (apply), what must follow (post, a formal statement relating the state before and after), and a proof that the first meets the second whenever the move is enabled.

dispatch is the only way a list of moves becomes an update, so an app cannot react to input except through a move. The theorems at the end say so formally.

This module is pure and imports nothing from Lean: it is linked into the host. The commands that build moves live in Cairn.Claims (compile time only).

Imports Cairn.Input, Cairn.Claim

Handler (S : Type) (enabled : S → Nat → Bool) : Type

How a move answers one kind of action. post relates the state before, the action, and the state after; sound is the proof that apply meets post whenever the move is enabled for the action's key. Cairn.Claims.dispatch_cases

provedlean/Cairn/Claims/Move.lean:180
dispatch_cases {S : Type} (moves : List (Move S)) (s : S) (a : Action) :
  dispatch moves s a = (s, []) ∨
    ∃ m,
      m ∈ moves ∧
        ∃ h,
          h ∈ m.handlers ∧
            m.id = a.claim ∧
              h.trigger = a.trigger ∧
                m.enabled s a.key = true ∧ dispatch moves s a = h.apply s a

Dispatch either leaves the state alone and emits nothing, or it is exactly one enabled handler of one move in the list that owns the action's claim and answers its trigger.

Every effect comes from a move. Each effect dispatch emits was emitted by the apply of an enabled handler of a move in the list that owns the action's claim.

dispatch_preserves {S : Type} {moves : List (Move S)} (P : S → Prop)
  (hP :
    ∀ (m : Move S),
      m ∈ moves →
        ∀ (h : Handler S m.enabled),
          h ∈ m.handlers →
            ∀ (s : S) (a : Action),

A property every enabled handler preserves is preserved by dispatch. This is how an invariant is proved one move at a time.

What dispatch guarantees

Preservation, one handler at a time

An invariant is preserved by dispatch when every handler of every move preserves it. The move command generates name.preserves, which turns obligations stated in the move's own terms (its apply, its binders) into Move.Preserves.

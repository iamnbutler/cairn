Cairn.Fuzz.Walk

lean/Cairn/Fuzz/Walk.lean

The walk

One sequence: a window size, text metrics, and operations generated from the current state (or replayed from a list), each checked against the app's claims (docs/fuzz.md).

An app with an App is driven through the real runtime (Runtime.route and Runtime.step): an action is performed as the pointer and key events a person would use, so hit testing, focus and routing are exercised along with the app. A machine without an App gets its actions directly (machine.update).

Imports Cairn.Fuzz.Target, Cairn.Fuzz.Text, Cairn.Fuzz.Metrics, Cairn.Runtime, Cairn.Layout.Check, Std.Data.HashMap, Std.Data.HashSet

Performed (S : Type) : Type

The result of performing one operation.

Fields

The actions delivered to update, in order.

ran : Bool

Whether the operation ran at all (an act whose control is missing is skipped).

maxNs : Nat

The slowest event's Runtime.step (update, view, layout, settle), in nanoseconds.

dropped : Bool

A press or double press the runtime dropped by design: its pointerDown delivered a blur, and after that step the pressed control is no longer at the point, so the release lands elsewhere and presses nothing (docs/runtime.md; TodoMVC decision T33 in docs/plan.md: the edit saves first, and if saving moved what was clicked, the click is dropped). This is exactly where Runtime.click_presses's hypothesis fails, so "performed" does not apply.

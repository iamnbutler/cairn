The cairn tool

The command line for Cairn packages. It starts a package, adds dependencies, builds, documents and publishes; checking, running and shipping are still the repository's make targets.

What works today

cairn has six commands: new, add, build, doc, publish and login. They have unit tests and have been run against a stand-in registry. Cairn has one public registry, https://cairn.registry.nexthub.sh, but its host isn't live yet (issue #97). Until it is, cairn add and cairn publish have nowhere to go, and an app requires Cairn from git at a tag instead (how). Nothing installs cairn yet; build it from a Cairn checkout.

Building it

cairn is its own Swift package in Cairn's tools/cairn, with no dependencies:

Commands

CommandWhat it does
cairn new <name> [--lib|--bin]starts a package in a new directory: cairn.toml with its kind, an empty claims.lock, and lean/ with a lakefile that sets the claim scope to <name> and requires Cairn. An app (--bin) also gets Package.swift and Sources/; a library (--lib) doesn't. With neither flag it asks which.
cairn add [<owner>/]<name>[@<range>]adds a dependency from the registry to cairn.toml and the lakefile, replacing a require … from git of it. It prints the Package.swift line rather than editing Swift. With no range it uses ^ and the latest release, and with no owner it looks up the name's owner. It needs no login.
cairn build [--release]lake cache get (prebuilt Lean from the registry, when it has it), lake build, Cairn's cairn-link to merge the Lean into one static library in .cairn/lib/, then swift build.
cairn doc [--private] [--open]the package's API docs, in build/doc/<name>/, the same pages as Cairn's own, with every claim on its module's page.
cairn publish [--owner <login>] [--dry-run]publishes the commit at the tag v<version>, which must be HEAD with a clean tree: its source, its claims.lock and its prebuilt Lean. It publishes under the login your token belongs to, or under an Org you can write to with --owner; a name's first publish makes that account its owner. The registry refuses a version that drops, renumbers or redefines a claim id. It takes no docs from a publisher; they will be built from the source (issue #94).
cairn loginchecks a nexthub token with package:write, read from standard input, and saves it. Only cairn publish needs it: anyone reads the registry, and Lake, git and SwiftPM fetch from it with no credential.

cairn uses the public registry, https://cairn.registry.nexthub.sh. CAIRN_REGISTRY points it at another, such as a local nextpm, and CAIRN_TOKEN gives a token without cairn login, as CI needs.

cairn.toml names the package, its version and the Lean libraries to link. Its name has to match the lakefile's package name and the claim scope, and cairn build and cairn publish check that all three agree.

Developer docs

Cairn docs

How to build a Mac app in Cairn, where everything a person can do is a claim with a durable id and machine-checked evidence.

Cairn apps are written in Lean 4. The app's state, its view, its layout, its hit testing and its text editing are pure Lean functions, and every thing a person can do is a claim: an id like ^2, a sentence saying what happens, a formal statement, and a proof that the code meets it. A thin Swift host runs the app on macOS and paints it with Metal.

These docs are young. Pages that today's code supports are written; the one that isn't says what it will cover and what has to land first. Every code sample is included from a source file that make check compiles, so a sample can't drift from the code it shows.

What works today

Cairn is research, and its API has no stability promise before 1.0. It is a package, though: an app lives in its own repository and depends on a tagged release (the latest is v0.1.2), and the cairn tool starts, builds and documents it. Yap is the first app built that way. Checking, fuzzing, mapping and bundling an app are still the Cairn repository's make targets; see the cairn tool.

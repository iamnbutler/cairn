Developer docs

Cairn docs

How to build a Mac app in Cairn, where everything a person can do is a claim with a durable id and machine-checked evidence.

Cairn apps are written in Lean 4. The app's state, its view, its layout, its hit testing and its text editing are pure Lean functions, and every thing a person can do is a claim: an id like ^2, a sentence saying what happens, a formal statement, and a proof that the code meets it. A thin Swift host runs the app on macOS and paints it with Metal.

These docs are a first skeleton. Pages that today's code supports are written; the rest say what they will cover and what has to land first. Every code sample is included from a source file that make check compiles, so a sample can't drift from the code it shows.

What works today

Cairn is research, not a released library. There is no package to depend on yet: an app lives inside the Cairn repository, next to the examples, and you build it with the repository's make targets. Making Cairn a package an app can depend on is issue #75.
